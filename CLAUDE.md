# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project: RideUp — Intercity Carpool Booking

Vietnamese intercity ride-sharing platform (university course project). One **Spring Boot monolith** backend + three **Expo / React Native** apps (customer, driver, admin). UI strings, comments and commit messages are mostly Vietnamese — keep that style.

```
RideUp/
├── rideup-backend/            Spring Boot 3.3.5, Java 21, Maven  (com.rideup)
├── rideup-customer-mobile/    Expo app for passengers (Stripe PaymentSheet, maps)
├── rideup-driver-mobile/      Expo app for drivers (register, vehicles, trips, bookings)
├── rideup-admin-mobile/       Expo app for admins (approve drivers / vehicles, stats)
├── db/                        create_database.sql, ad-hoc fix/migration scripts, _backup/V1__init.sql
├── SETUP.md                   Full local setup guide (Vietnamese) + troubleshooting
└── thuat-toan-ranking-tim-chuyen.md   Design note for the trip-search ranking algorithm
```

## Commands

### Backend (`cd rideup-backend`)

```bash
mvn spring-boot:run                 # run (profile `local` is active by default)
mvn clean package -DskipTests       # build target/rideup-backend-0.0.1-SNAPSHOT.jar
mvn test                            # there is no src/test yet — add tests under src/test/java
mvn -Dtest=ClassName#method test    # single test
```

Swagger UI: `http://localhost:8080/api/swagger-ui.html`. All routes live under context-path **`/api`**.

### Mobile apps (`cd rideup-<customer|driver|admin>-mobile`)

```bash
npm install
npx expo start -c        # -c clears Metro cache; press w / a / i, or scan QR
npm run web              # browser
```

No lint/test tooling is configured in the mobile apps.

## Local infrastructure

| Service | Default | Notes |
|---|---|---|
| MySQL 8 | `localhost:3306/rideup`, `root/root` | Schema is generated by Hibernate (`ddl-auto: update`, Flyway disabled). |
| Redis | `localhost:6379` | Required — access-token whitelist. App won't authenticate without it. |
| MongoDB | `MONGO_URI` | Dependency present but **all Mongo autoconfig is excluded** in `application.yml`. Chat tables currently live in MySQL. |
| Stripe | test keys | `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`. Local webhooks: `stripe listen --forward-to localhost:8080/api/payments/webhook`. |

Env overrides: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `REDIS_HOST/PORT/PASSWORD`, `JWT_SECRET` (≥ 32 bytes), `UPLOAD_DIR` (default `uploads/`), `BOOKING_PENDING_MINUTES`, `LOCATION_SEED_*`.

`application-local.yml` and `.env` files are **git-ignored** — they hold real local secrets. Never move secrets into `application.yml` or commit them.

On first boot `LocationDataSeeder` seeds Vietnamese provinces/wards from the Overpass API (with retry/backoff); disable with `LOCATION_SEED_ENABLED=false` when offline.

## Backend architecture

Layered package structure under `com.rideup`:

```
controller/   REST controllers, role-gated with @PreAuthorize
service/      business logic (BookingService, TripService, PaymentService are the big ones)
repository/   Spring Data JPA
entity/       JPA entities (UUID String ids, Lombok @Builder, EnumType.STRING, @Version where concurrent)
dto/request, dto/response
exception/    ApiResponse, AppException, ErrorCode, GlobalExceptionHandler
security/     JWT filter, JwtService, WebSocket handshake/channel interceptors, SecurityConfig
config/       Redis, RestTemplate, Stripe, WebMvc (serves /uploads), WebSocket (STOMP)
constant/     RedisKey prefixes, RedisKeyTTL
enums/        BookingStatus, PaymentStatus, PaymentMethod, TripStatus, DriverStatus, Role, ...
```

### API conventions

- Every controller method returns `ApiResponse<T>` (`{ code, message, data }`) via `ApiResponse.success(data)` / `success(message, data)`. Don't return raw `ResponseEntity` or entities in new code.
- Errors: `throw new AppException(ErrorCode.X)` (preferred — add new codes to `ErrorCode`) or the factories `AppException.badRequest/notFound/forbidden/conflict(...)`. `GlobalExceptionHandler` shapes the JSON.
- Current user id: `((UserDetails) auth.getPrincipal()).getUsername()` — the "username" is the user **id**, not the email.
- Role gating by URL prefix: `/customer/**` → CUSTOMER, `/driver/**` → DRIVER, `/admin/**` → ADMIN (class-level `@PreAuthorize`). `TripController` mixes roles per method.
- Public routes (see `SecurityConfig`): `POST /auth/**`, `POST /driver/register` (multipart, CCCD + GPLX images), `/locations/**`, `/ws/**`, swagger, `POST /payments/webhook`, `POST /payments/wallet/confirm`. Anything new that must be public goes there.

### Auth

- `POST /auth/authentication` (login), `/register`, `/logout`, `/refresh-token`.
- Access token = HS256 JWT (15 min), **whitelisted in Redis** at `auth:access:<token>`; `JwtAuthFilter` rejects tokens missing from Redis → logout/refresh revoke by deleting the key.
- Refresh token = random UUID stored SHA-256-hashed in `refresh_token` (30 days), rotated on every refresh; daily 02:00 cleanup job.
- Drivers must be APPROVED by an admin (`DriverStatus`) before they can create trips; vehicles also need admin approval.

### Core domain flow

1. **Driver** registers → admin approves driver + vehicle → driver creates a `Trip` (start/end `Province`, optional `TripStop`s with `Ward`s, `seat_total/seat_available`, optimistic `@Version`).
2. **Customer** searches: `POST /trips/search` (by departure time) or `POST /trips/search-ranking` (weighted score: time 35% / price 30% / driver rating 20% / pickup distance 15%, min-max normalised — see the ranking `.md`).
3. **Booking** (`POST /customer/bookings`) with `PaymentMethod` `CASH` or `STRIPE`:
   - `PENDING_PAYMENT` → (Stripe hold succeeds, or CASH) → `WAITING_DRIVER_APPROVAL` → driver `confirm` / `reject` → `CONFIRMED` / `REJECTED_BY_DRIVER`.
   - Terminal: `COMPLETED`, `CANCELLED_BY_USER`, `CANCELLED_BY_DRIVER`, `CANCELLED_PAYMENT_FAILED`, `EXPIRED`.
   - A scheduler expires stale pending bookings (`app.booking.pending-expiration-minutes`, default 15).
   - Seats are reserved against trip version (`trip_version_at_reserve`) — keep optimistic locking intact when touching seat logic.
4. **Payment (Stripe, manual capture)**: `POST /payments/create-intent { bookingId }` → client secret → mobile `presentPaymentSheet()` → `POST /payments/{id}/authorize` (backend verifies PI is `requires_capture`) → `PaymentStatus.HOLDING`. Trip `complete` captures (`PAID`); trip/booking cancel voids or refunds (`VOIDED` / `REFUNDED`). Webhook is idempotent on `event.id`. **Amount is always computed server-side — never accept it from the client.**
   - `/payments/wallet/deposit` (driver commission top-up) is a Phase-B stub.
5. **Trip lifecycle** (driver): `OPEN/FULL → STARTED → COMPLETED` or `→ CANCELED` (auto-refunds active Stripe bookings).
6. **Review**: `POST /customer/reviews/{tripId}` after the trip is completed.

### WebSocket (STOMP)

`WebSocketConfig`: endpoint `/api/ws?token=<accessToken>` (no SockJS), simple broker on `/topic` + `/queue`, app prefix `/app`, user prefix `/user`. `JwtHandshakeInterceptor` validates the token at handshake; `WebSocketAuthChannelInterceptor` sets the principal per message. Currently used to push driver approval status to `/user/queue/status`. `Conversation` / `Message` / `CallSession` / `Notification` entities exist but chat & notification endpoints are **not implemented yet** — new realtime features should reuse this config and `convertAndSendToUser(userId, ...)`. Remember to add new frontend origins to `setAllowedOrigins` here as well as in `SecurityConfig`.

### Database notes

- Hibernate owns the schema. `db/_backup/V1__init.sql` is reference only and has drifted (e.g. role table naming); don't treat it as source of truth.
- `db/*.sql` are one-off manual fix scripts (ward codes, booking-status migration, cleanup) — when you change an enum or column that existing rows depend on, add a similar script rather than relying on `ddl-auto`.
- Images (CCCD, GPLX, avatars) are stored on local disk in `rideup-backend/uploads/` via `FileService` and served by `WebMvcConfig`.

## Mobile apps

All three share the same layout: `App.js` → `src/{api/api.js, auth/AuthContext.jsx, navigation/AppNavigator.jsx, screens/, components/, theme.js}`. React Native Paper + React Navigation, axios, AsyncStorage, Inter font.

- **API base URL** (`src/api/api.js`): web → `localhost:8080/api`; native → LAN IP derived from Expo `hostUri`; then `EXPO_PUBLIC_API_URL` / `app.json extra.apiUrl`. All API helpers live in `api.js` and unwrap `r.data.data` — add new endpoints there.
- Axios interceptor attaches `Bearer` token from AsyncStorage; on 401 it clears storage and emits `rideup-auth-expired`.
- Admin app uses separate storage keys (`adminToken`, `adminUser`) and rejects non-ADMIN users.
- **Customer Stripe**: `@stripe/stripe-react-native` is native-only. `App.web.js` and `hooks/usePayment.web.js` are web variants without Stripe; STRIPE payment is blocked on web. Stripe requires a dev client build (`expo-dev-client`), not Expo Go. Keep any native-only import behind `.native.js` / `.web.js` splits (see `MapSection.native.jsx` / `.web.jsx`).
- Driver app gates `MainTabs` on driver status; unapproved drivers see `DriverStatusScreen`.
- Styling: use `FONT[weight]` from `theme.js` for every bold text (otherwise web fakes bold) and the `shadow()` helper instead of raw iOS shadow props. Don't call `updateUser()` inside a mount `useEffect` (it resets navigation) — see SETUP.md troubleshooting.
- Library versions differ slightly between apps (customer is on React Navigation 7, driver/admin on 6) — check the app's own `package.json` before using an API.

## Gotchas

- `ddl-auto: update` never drops/renames columns — renamed fields leave stale columns behind.
- Booking/Trip status enums were refactored; old rows may need `db/migrate-booking-status.sql`.
- `.claude/` and `.kilo/` are git-ignored tool folders.
